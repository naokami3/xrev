1xrev とは — 全体構成

xrev は、primary（設計・実装・修正反映を担うエージェント）が書いたプランやコードを、 別ペインに常駐する reviewer（レビュー専用・read-only）へ自動送付し、 critical/high の指摘が 0 件になるまで往復させる Claude Code プラグイン。 役割は設定で決まり、既定は primary=Claude / reviewer=Codex（主従反転プリセットで逆転可能）。 エージェント間のやり取りに中間ファイルは使わず、cmux の制御ソケット経由でペイン間通信する。

21 回の依頼が流れる道

依頼文に @xrev（設定のキーワード）が含まれるか、明示指示があると発火する （どちらも無ければ完全に沈黙）。往復は設計フェーズ （実装前にプランを潰す）→実装フェーズ（diff をレビュー）の 2 段で、 どちらも同じループを回す。収束後の完了アクションは既定が最も安全な review で、 PR を作る場合も必ずドラフト — 確定の最終トリガは常に人間が引く。

3cmux の何を使い、どう実現しているか

xrev はエージェント間通信に cmux（macOS のターミナル）の制御ソケットと CLI （send / send-key / read-screen / tree / top / new-pane / rename-tab）を使う。ただし cmux には公式ドキュメントに無い実挙動が多数あり、 送信 1 回は下図のパイプラインでそれらに対処している。

4暴走・誤配送させない仕組み

「終わらせる判断」は LLM に任せず、スクリプトが決定論的に握る。review-loop.sh は 1 ラウンドごとに decision を返し、primary はその値だけで分岐する（終了コードでは判断しない）。

このほか全体を貫く原則は fail closed（判定できないときは送らない・進めない）:

  • 収束は verdict（reviewer の自己申告）ではなく blocker 件数 0 の機械判定。
  • 送信完全性を検証できない組み合わせ（未知の reviewer 種別、claude への inline 送信）は送信前に拒否。
  • reviewer の read-only は起動引数の付与だけでなく、実 argv の意味検証を毎送信ゲートで行って強制。
  • @xrev（キーワード）や明示指示が無ければ完全に沈黙し、既定では commit / pr に進まない。

守れる範囲と限界（何を保証しないか）は security-design.md に正直に書いてある。
