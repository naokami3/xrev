# ADR-003: 主従反転プリセット（primary=codex / reviewer=claude）は参照モード専用の claude reviewer として提供する

## Status: Accepted

## Context
roadmap の積み残しであった Codex 主・Claude レビュー構成を実装するにあたり、コアの主従非依存原則（config 切替）を保ちながら、(1) reviewer バイナリ解決の codex 固定、(2) 送信完全性検証（切り詰め検出）の Codex TUI 文言固定、(3) codex 主の発火・プレイブック導線の欠如、(4) プリセット config の不在、(5) ドキュメントの claude 主前提、という 5 つの固定点を解消する必要があった。Claude Code TUI の実測（R1〜R6）で「ペーストチップは連番表示のみで文字数が出ない」「約 900 文字以上は本文が read-screen で復元できない」「最小 wire（プロトコル指示部込み）は約 3.2k 文字」という事実が判明し、codex と同等のチップ文字数照合も、当初設計した全文一致照合も、実運用サイズの inline 送信では完全性を証明できないことが確定した。あわせて安全ポリシー実効検証の argv 取得が ps の表示文字列の空白分割に依存しており、空白入り単一引数（cmux 自動注入の --settings <JSON> 等）内の偽フラグを誤認し得る問題、および用語「到達点」「配管」の分かりにくさも扱った。

## Decision
claude reviewer は参照モード専用とする。inline 送信は wire 長に関わらず送信前に無条件拒否（新設 exit 28 = integrity_unverifiable）し、レビュー対象の完全性は「primary と reviewer が同一コード（transport.sh diff-hash）で取得した diff 内容ハッシュ + 基底 HEAD OID の端到端照合」のみを根拠とする。この帰結として、コードの無い設計フェーズのクロスレビューは claude reviewer では非対応（既知の制約として明文化し、人間レビューまたは codex reviewer 構成を案内）。reference_unverified からの回復は reviewer 種別依存とし、codex=inline 再試行 / claude=参照モードのまま再試行（総量規制は既存 max_reference_fallbacks を流用）。安全ポリシー実効検証は sysctl KERN_PROCARGS2 による argv 境界保持取得へ置き換え、PID 受領から合否判定まで単一 python3 プロセス内で完結させる（区切り文字表現を bash へ戻さない。取得不能は exit 27 で fail closed）。reviewer バイナリは XREV_REVIEWER_BIN > XREV_CODEX_BIN（reviewer=codex のときのみの後方互換）> config reviewer 値で解決。codex 主の導線は AGENTS.md ではなく references/codex-primary-playbook.md（手順書）+ scripts/print-agents-snippet.sh（利用者プロジェクトの AGENTS.md へ貼るスニペットを stdout 出力。埋め込みは安定 checkout の XREV_ROOT 1 点のみ）で提供し、発火判定は scripts/keyword-match.sh に単一真実源化して hook と共有する。用語は「到達点」→「完了アクション」、「配管」→「通信層」に統一（キー名・スクリプト名・env 名・exit code は不変）。

## Consequences
利点: 完全性を証明できない受理経路が存在せず fail closed 原則が貫徹される。参照モードの照合はレビュー対象そのものの同一性を端到端で機械保証するため、TUI の表示仕様変更に依存しない。argv 境界保持により空白・TAB・改行入り単一引数内の偽フラグが構造的に排除される。keyword 判定・バイナリ解決・ポリシー判定の実体が各 1 箇所に集約され二重管理が消えた。妥協点: claude reviewer では設計フェーズのクロスレビューができない（実装フェーズ専用）。参照 payload 自体の切り詰めは画面照合しない（補助文の欠落は起こり得るが、diff_hash/HEAD 照合と reviewer の復号契約により『見ていない対象への approve』は成立しない）。KERN_PROCARGS2 は macOS 専用・非公開レイアウト依存（doctor に自己診断を追加して縮退を可視化）。実機 e2e（別プロジェクトの Codex からスニペット経由で 1 往復・claude reviewer との実機往復）は未検証で roadmap フェーズ 5 に残る。
