# ADR-004: reviewer は primary の相手方へ auto 解決し、codex 側の導入はグローバル AGENTS.md への一度きり追記とする

## Status: Accepted

## Context
主従反転プリセット（ADR-003）の導入 UX に対し、利用者から (1) プロジェクトごとのスニペット貼り付けはライブラリ依存の押し付けとして嫌われる、(2) 起動しているエージェントが primary となり相手方が自動で reviewer になるべき、という指摘を受けた。claude 主は既にプラグイン機構でゼロ設定だったが、codex 主はプラグイン機構が無く per-project の AGENTS.md 追記に頼っていた。また主従の切替に XREV_CONFIG によるプリセット明示が必要だった。実測 R7 により codex がグローバル $CODEX_HOME/AGENTS.md（既定 ~/.codex/AGENTS.md）を全セッションで読むことを確認し、マシン単位の一度きり導入が成立すると確定した。

## Decision
config の reviewer に "auto" を導入して既定値とし、「primary の相手方」（claude↔codex の 1 対 1 マップ・transport.sh 内 1 箇所）へ決定論的に解決する。primary は入口の自己申告（スキル=XREV_PRIMARY=claude / プレイブック=XREV_PRIMARY=codex）→ config → 既定 claude。解決済み reviewer 名を semantic kind として安全ポリシー検証・送信完全性方式・launch 引数・composer クリアの唯一の種別判定源とし、reviewer_process は前景 comm 照合専用に分離。派生 3 キー（pane_title / process / reads_workspace）も既定 auto で導出し、明示値との種別矛盾は副作用前の共有ゲート（送信・ペイン生成・exec の直前）で exit 29 = reviewer_config_conflict として fail closed。レビュアーの質問は「明示=正規上書きで質問なし・意図が一意に読めない場合のみ質問」に最小化。codex 側の導入は print-agents-snippet.sh --append-global によるグローバル AGENTS.md へのマーカーブロック冪等追記とし、per-project 貼り付けを廃止。追記は正規対象表現（lstat 分岐順・symlink 実ファイル解決・未作成は CODEX_HOME 正規化）・親ディレクトリ固定名の mkdir ロック（TMPDIR 非依存・競合は待機せず拒否）・マーカー 0/1 対のみ許容・一時ファイルとパーミッション引き継ぎと mv・mv 直前の lstat 種別/st_dev/st_ino/mode/内容 digest 再検証で保護し、対象解決から書き込みまでを単一 python プロセスに統合してパスが bash の command substitution を通らない構成とする。

## Consequences
利点: 利用者プロジェクトへの追記が不要になり、@xrev だけで「起動中のエージェント=primary・相手方=reviewer」が成立する（通常フローの質問ゼロ）。既定 config + 宣言なしは従来の claude 主・codex レビューと完全同値（後方互換）。プリセットは明示固定用として残置（等価性テストで担保）。妥協点: claude reviewer の設計フェーズ非対応（ADR-003 の制約）は導入 UX を変えても残るため、一拍確認で必ず提示する。グローバル AGENTS.md 追記は codex のグローバル読込仕様（実測確認済み）に依存する。入口の自己申告（XREV_PRIMARY）は信頼モデル上は宣言ベースであり、偽宣言は相手方の取り違えを生み得るが、送信ゲート（プロセス証明・ポリシー実効検証）がレビュー安全性を守る。
