# ADR-002: 安全性リファクタリング（fail-open の除去・read-only 強制・バージョン耐性）

## Status: Accepted

## Context
cmux / Claude Code / Codex CLI のバージョンアップのたびに xrev が動作しなくなる事象が続いていた。壊れ方が「全拒否」「タイムアウト」「無言沈黙」に化けて原因を特定できず、ユニットテストは全緑のまま実機でだけ壊れる構図（過去にプロセス証明が実機で全ペイン拒否になった実績あり）。加えて調査で、config の型ミスで critical を残したまま converged になる誤収束、env 由来の値が無検証で bash 算術に入る経路、開発フックが検証を黙ってスキップする fail-open が判明した。SKILL.md が約束する「reviewer は read-only」も実装では強制されていなかった。

## Decision
17 の論理変更に分けて修正した。(1) 誤収束の除去: severity_blockers の型検証と decode_error の常時 blocker 化、round_state 破損時の安全弁カウンタ飽和。(2) 入力検証の一貫化: 算術式に入る全数値を _xrev_uint（正整数+キー別範囲+桁数上限）で検証し、算術インジェクションと busy-loop と 64bit 溢れを封じる。(3) 誤診断の解消: 完成しているが不正な応答を _scan_broken_blocks で検出して exit 24（invalid）とし timeout と区別、Enter 送信失敗を exit 25 で区別、巨大 payload を stdin 経由に変えて Linux の MAX_ARG_STRLEN 超過（ubuntu CI が現に赤だった）を解消し wire 長上限 exit 26 を設ける。(4) reviewer の read-only 機械強制: 拒否リスト方式ではなく最終 argv を解析して sandbox=read-only かつ承認=never が一意に有効であることを検証する方式を正典とし、launch 引数決定時・start-reviewer の最終 argv・起動後の実効確認・既存ペイン採用時の 4 箇所で共有する。プロセス証明と同一ゲートで送信経路の全 4 ゲートに適用し TOCTOU を塞ぐ。(5) 診断可能性: 外部ツール契約を一括検査する transport.sh doctor を新設し、バージョンアップ後はまず doctor を実行する運用にした。(6) fail-closed 化: 開発フックの検証スキップ、finalize の detached HEAD と base 決め打ち、make-adr の素材未検証と上書き採番を是正。

## Consequences
テストは 376 件から 582 件に増え、ubuntu CI の失敗も解消した。可用性は一部下がる（安全ポリシーを満たさない既存 reviewer ペインは既定で拒否され、opt-out は XREV_ALLOW_UNVERIFIED_REVIEWER=1 の明示指定のみ）。ポリシー検証をゲートごとに実行するため ps 呼び出しが増えるが、キャッシュは TOCTOU の再導入になるため行わない。残る限界: 同名バイナリへの差し替えや codex 自身の設定ファイルでの上書きは検出しない。最終ゲートと Enter 送出の間のごく短い競合窓は原理的に排除できない。Codex TUI の表示文言や cmux のエラー文言の変更は doctor でも検出できない。
